# Node #94 action-signable component

This standalone crate is an independently authored, offline reconstruction of
the bounded action-signable behavior retained for Linux x86-64 node #94,
SHA-256
`3b7179cd967d1b13b683e05debfc685ad4c750e918226402d5d575eff1c0459f`.
It has no dependencies and does not use the unlicensed reference tree as an
implementation source.

The caller supplies already-serialized action bytes. The crate appends the
established context suffix, computes Keccak-256, and constructs typed records
for the two observed output families. It does not serialize actions, construct
an EIP-712 domain, sign data, handle private keys, broadcast transactions, or
perform network or chain operations.

## Implemented contract

The connection preimage is:

```text
encoded_action
++ nonce.to_be_bytes()
++ (0x01 ++ vault_address[20] | 0x00)
++ (0x00 ++ expires_after.to_be_bytes() | empty)
```

`expires_after = Some(0)` remains distinct from `None`. The selector is not
part of this preimage.

`keccak256` implements Keccak-f[1600] with 24 rounds, a 136-byte rate, the
Keccak `0x01` delimiter, multi-rate final bit `0x80`, and a 32-byte result. It
is deliberately Keccak-256, not FIPS SHA3-256.

The agent record contains source byte `a` only for selector 3 and `b` for all
other selector bytes, the connection digest, chain ID 1337, and an explicit
zero-verifying-contract marker. The embedded record separately preserves the
observed copied 32-byte input, connection digest, nonce, and selector byte.

Allocation and length failures from preimage construction are returned as
`BuildError`. Vault addresses and both 32-byte fields use fixed-size types;
slice constructors reject malformed lengths.

| target Keccak initialization and constants | rate 136, delimiter `0x01`, 24-round Keccak-f[1600] | `keccak.rs` plus permutation, empty, block-boundary, and multi-block known answers |
| `action-wire-rmp-signable-94` | serializer call boundary and unresolved wrapper/canonicalizer dependency | caller-supplied `EncodedAction`; no serializer is implemented |

The 1,008-row test reads the accepted evidence table directly. The small local
input table retains the deterministic byte inputs whose seed and construction
are defined by `tools/action_signable.py`; expected digests remain in the
pre-existing evidence packet and are not generated by this Rust code.

- `build_preimage`, `preimage_len`, and `signing_suffix_len`
- `keccak256` and the target-observed Keccak constants
- `connection_id`
- `build_agent_payload` and `build_embedded_payload`
- `EncodedAction`, `SignableContext`, `VaultAddress`, `ChainSelector`
- `ConnectionId`, `SignatureChainId`, `AgentPayload`, `EmbeddedPayload`
- `BuildError` and `FixedBytesError`
- `TargetContextLayout`, `TargetFunction`, and the pinned target digest

The target-layout constants document evidence offsets and FDE ranges only;
they are not a claim that these safe Rust types reproduce the private ABI.

`tools/action_signable.py` can regenerate the evidence packet into a fresh
temporary directory. It statically reads and models the pinned artifact; it
does not execute the captured node.

## Deliberate limits

The action MessagePack layout and the wrapper/canonicalizer immediately above
the serializer are unresolved, so `EncodedAction` is intentionally opaque.
The crate does not infer action schemas, field ordering, signing domains,
signature algorithms, recovery IDs, key handling, or transaction submission.
It also does not reproduce allocator failures, unwind payloads, private target
types, struct ABI, or target code generation.

Matching connection digests establishes this bounded byte relation, not source
identity, binary identity, complete signing behavior, or whole-node recovery.
No component-completion or progress gate is advanced by this crate.
